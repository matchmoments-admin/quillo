# Access control standard

> Schedule 2, Part 2, control requirement 1 (controls 1(a)–1(h)). Version 0.2, 2026-10-08
> (0.2: app-side enforcement from #638 — admin MFA gate, API rate limiting, just-in-time admin rule, review-log template).

## 1. Principles

- Every person has their own account; no shared human logins.
- MFA on every account that can reach production, code, secrets or CDR data.
- Least privilege by default; administrative rights only while needed (just-in-time).
- Access is reviewed every quarter and removed promptly when no longer needed.
- Consumer access to their own data (through the app) is governed by Clerk and the app's tenant isolation;
  the MFA control 1(a) does not apply to consumers.

## 2. Multi-factor authentication

Required method: **passkey or hardware security key** where offered, otherwise an **authenticator app**
(TOTP). SMS only where nothing else is offered. Store recovery codes in the password manager, not on the
laptop desktop or in email.

(ASD and NIST SP 800-63B guidance); change immediately on any suspicion of compromise. Lockout and rate
limiting are provided by each provider. For consumers, Clerk enforces password strength, breached-password
detection, rate limiting and lockout (to be confirmed and screenshotted in the Clerk production instance —
[clerk-production-cutover.md](clerk-production-cutover.md) step 4). Quillo's own API adds a general
per-IP and per-user request limit on top (flag `api_rate_limit`, §8).

## 3. Least privilege and role-based access

**Application roles** ([`src/lib/roles.ts`](../../src/lib/roles.ts)): `individual` (default),
`admin`, `accountant`, `bookkeeper`, `support`, `partner`. Checks are server-side. Every query is scoped by
the `user_id` derived from the verified session. The `admin` role is the only cross-tenant role; its
routes ([`src/api.ts`](../../src/api.ts), `resource === "admin"`) return platform aggregates (overview,
tenant list, AI spend) and role assignment. Admin must never be given a route that returns another
tenant's transactions; any such route needs a separate decision and its own logging.

**Infrastructure:**

## 4. Administrative privileges (just-in-time)

- **App `admin` role — the just-in-time rule (#638).** Admin is a cross-tenant capability, so it is
  treated as a privilege you *pick up for a task*, not a standing attribute:
  1. **Standing holder:** the founder's own tenant only. No other account holds `admin` by default.
  2. **MFA is a precondition, enforced by the server.** With `admin_mfa_required` ON, every `/api/admin/*`
     route refuses (403 `admin_mfa_required`) unless the Clerk session verified a second factor
     (`fva` claim) within the last 12 hours. A stolen password alone cannot reach an admin route, and a
     stolen long-lived session stops working for admin once its second-factor check is 12 hours old.
  3. **Use for a specific task only** (spend review, tenant support with the user's consent, role change,
     security page for Fiskil). Sign in, do the task, sign out — don't browse admin pages idly.
  4. **Granting admin to anyone else** (`PUT /api/admin/tenants/:id/roles`): only for a written purpose
     and an **end date**, recorded in the §5 log *before* the grant; the grantee must have MFA enrolled
     first (the gate refuses them otherwise). Remove the role on the end date and record the removal.
     A grant with no end date is a finding at the next quarterly review.
  5. **No admin route may return another tenant's transactions or documents**; admin sees aggregates,
     counts and ids (see §3). Adding such a route needs its own decision and logging.
  6. **Kill-switch:** if an admin account is suspected compromised, remove the role via SQL
     (`UPDATE profiles SET roles = '["individual"]' WHERE user_id = ?`), revoke the user's sessions in
     the Clerk dashboard, then rotate any secret the session could have seen.
- **Cloudflare / AWS / GitHub admin:** the director is the only admin. The laptop's daily macOS account is
  a standard user ([endpoint-standard.md](endpoint-standard.md)); elevation needs the separate admin
  password.
- **Production data access:** direct D1 queries against production happen only for a recorded reason
  (migration, incident, directed deletion, support request with the user's consent). Record the reason in
  the PR or incident entry.
- **Break-glass:** if the director is unreachable during a SEV-1, the backup contact follows the sealed
  instructions to notify Fiskil; they do **not** receive production credentials.

## 6. Joiners and leavers

Today there are no staff. Before anyone else gets any access to the CDE or to production tooling:

**Joiner**
1. Police check and reference check complete ([training-and-screening-record.md](training-and-screening-record.md)).
2. Security and privacy training complete; acceptable use policy signed ([acceptable-use.md](acceptable-use.md)).
3. Named account created for them (never share the director's); MFA enrolled at first login.
4. Minimum role only; time-bound if admin; written in the access review log.
5. Endpoint meets [endpoint-standard.md](endpoint-standard.md) before access.

**Leaver (same day as departure, or immediately on termination)**
1. Disable or remove every account in §2 they held; revoke sessions and tokens.
2. Rotate any shared secret they could have seen (Worker secrets, API keys).
3. Recover or wipe devices holding company data.
4. Record in the access review log.

**Mover:** treat a role change as a leaver for the old rights plus a joiner for the new.
